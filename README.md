# Accident Video Analysis Tool (AVAT)

사고별 영상을 프레임 단위로 검토하면서 조사 항목을 입력하고, 임시저장·완료 처리한 결과를 CSV로 내보내는 PySide6 데스크톱 앱입니다.

## 주요 기능

- 13자리 사고번호 파일명을 기준으로 폴더 영상을 사고별 자동 분류
- 사고 목록과 사고별 복수 영상 관리, 확인 절차가 있는 사고·영상 삭제
- 메뉴·작업 폴더 탭·조사/통계 보기 전환을 한 줄로 배치, 현재 탭/새 탭 열기 선택
- 프로젝트 폴더의 새 영상 자동 감지, 가져오기 시 작업 폴더로 복사 선택
- OpenCV 기반 재생/일시정지, 영상 소리 출력, ±1/10프레임, ±1초 이동, 프레임 번호 직접 이동
- 영상마다 트리거 `T` 1개와 충돌 `C` 1개 타임라인 마커 지정·저장
- 영상별 속도 기준 지점·구간 거리 입력, 구간 평균 속도와 T 시점 속도 추정·그래프
- 단일 프레임·타임라인 드래그·직접 입력 구간의 객체 검출(Grounding DINO), 트리거/충돌 관여 객체 라벨링과 조사 탭 반영
- 식별 구분을 우측 상단에 고정하고 조사 항목과 자유 텍스트 비고를 9개 탭으로 제공
- 사고 구분 번호 최대 13자리와 `20-24세`~`95-99세`의 5세 단위 운전 연령 선택
- 사고 당시 주행거리는 자리수 제한 없이 숫자로 입력
- 트리거 시점 사고 정보의 2열 입력 배치
- 숫자·길이·실제 날짜/시간·요일 일치 검증
- 거리 수치에 따른 범위와 사고일자(직접 입력·달력 선택)에 따른 요일 자동 입력
- 일요일부터 시작하는 달력과, 사고일자 아래의 회색 읽기 전용 사고요일 표시
- 장애물 유무 및 피해 확인 가능 여부에 따른 조건부 입력
- 논리적 필수 질문 기준의 `미입력 N` 표시
- SQLite 트랜잭션 기반 사고별 부분 저장, 완료 상태 관리, 다음 미완료 사고 이동
- 사고 1건당 1행의 UTF-8 BOM CSV 내보내기
- 선택한 사고별 Word 사고 분석 보고서(.docx) 자동 생성
- 프로젝트별 통계 탭: 개요·항목 분석·교차 분석·영상 지표·데이터 품질
- 통계 그래프/표에서 사고 조사로 이동, 조건 필터, PNG·CSV·PDF 내보내기

## 설치 및 실행

Python이 없는 PC나 폐쇄망 PC에는 **EXE 배포본**(`AVAT.exe` + 내장 라이브러리 폴더)을 사용합니다. 배포본 만들기와 설치는 아래 [다른 PC·폐쇄망 배포](#다른-pc폐쇄망-배포)를 참고하세요. 이 절은 소스 코드로 직접 실행하는 개발·검토용 방법입니다.

Python 3.11~3.13 환경을 권장합니다. 의존성 파일은 실행용 `requirements.txt`(본체 + 객체 검출)와 개발용 `local_dev/requirements-dev.txt`(실행용 + 테스트·린트) 두 개입니다. PyTorch는 PC의 GPU 드라이버에 맞는 휠을 먼저 설치하며, CPU 전용 PC는 아래 index URL을 `https://download.pytorch.org/whl/cpu`로 바꿉니다.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements.txt
python main.py
```

작업 폴더를 지정해 실행할 수도 있습니다.

```powershell
python main.py --workspace "D:\investigations"
```

처음 실행할 때 작업 폴더를 지정하지 않으면 Windows 문서 폴더 아래 `사고영상조사`를 사용하며, 이후에는 저장된 프로젝트 탭을 복원합니다. 앱의 **파일 → 프로젝트 폴더 열기**, 상단 **+** 또는 `Ctrl+O`로 프로젝트 폴더를 열 수 있습니다. 폴더를 선택하면 **현재 탭으로 불러오기 / 새 탭에서 열기**를 선택하며 기본 선택은 새 탭입니다. 이미 열린 폴더를 선택하면 해당 탭으로 이동합니다.

각 프로젝트는 자신의 폴더에 있는 `investigations.db`를 사용합니다. 메뉴 오른쪽의 배경색이 있는 문서 탭을 누르면 사고 목록·조사 양식이 전환되며, 전체 경로는 탭에 마우스를 올려 확인합니다. 긴 탭 이름은 가운데를 생략하고, 탭이 많으면 좌우 스크롤로 탐색합니다. 폴더명·경로를 메뉴나 왼쪽 패널에 중복 표시하지 않으며 왼쪽은 **사고 / 영상 목록**으로 시작합니다. 맨 오른쪽의 **조사 / 통계**는 문서 탭과 구분되는 두 칸 토글 버튼입니다. 탭의 닫기 버튼으로 프로젝트를 닫을 수 있으며, 마지막 프로젝트의 닫기 버튼은 비활성화됩니다. 현재 탭에서 다른 프로젝트를 열어도 이전 프로젝트의 저장 데이터는 해당 폴더에 보존됩니다.

프로젝트 폴더 탭을 좌우로 드래그하면 표시 순서를 바꿀 수 있습니다. 순서만 변경할 때는 현재 프로젝트의 입력 내용·영상 재생 상태·통계 조건을 유지하며, 사고 순서나 저장 폴더는 바뀌지 않습니다.

사고 / 영상 목록의 검색창 오른쪽 **사고번호 오름차순 정렬** 버튼은 현재 프로젝트 전체를 원래 사고번호의 숫자 순서로 정렬합니다(예: 2019년 → 2020년 → 2023년). 각 사고의 영상도 `_1 → _2 → _10` 순서로 정렬하고 바로 저장하므로 재실행 후 유지됩니다. 검색 결과만 정렬하는 것이 아니며 검색·펼침·다중선택·현재 재생 영상·프레임은 유지합니다. 번호·마커·박스·회전·완료 상태는 바꾸지 않습니다.

탭 전환·현재 탭 교체·탭 닫기 전에 변경 사항을 저장하며 실패하면 동작을 취소합니다. 탭을 오갈 때 검색어·사고 목록 펼침/선택 상태·조사 탭·영상 프레임을 복원하고 영상은 일시정지 상태로 엽니다. 비활성 프로젝트의 영상 디코더는 닫습니다.

열린 프로젝트 폴더 탭·드래그로 변경한 순서·마지막 선택 탭은 앱을 다시 실행해도 복원됩니다. Windows에서는 `%LOCALAPPDATA%\AVAT\project_tabs.json`에 폴더 경로와 선택 위치만 별도로 저장하며 사고 데이터는 각 폴더의 `investigations.db`에 그대로 유지합니다. 탭을 열거나 닫고 이동할 때 자동으로 기록하고, 정상 종료 시에도 최종 상태를 저장합니다. 재실행 시 선택된 프로젝트만 먼저 읽고 다른 탭은 선택할 때 읽습니다. `--workspace`를 지정하면 기존 탭은 유지한 채 해당 폴더를 선택하며, 처음 보는 폴더는 새 탭으로 추가합니다. 저장된 폴더가 없거나 외장 드라이브가 연결되지 않았으면 탭을 유지하고 읽기 오류를 표시하며, 없는 폴더를 자동 재생성하거나 기존 데이터를 덮어쓰지 않습니다. 연결 복구 후 같은 폴더를 다시 열면 재시도합니다. 검색어·통계 조건 등 실행 중 화면 상태까지 이 설정 파일에 저장하지는 않습니다.

## 기본 사용 흐름

1. 프로젝트 폴더를 처음 열면 그 폴더 바로 아래의 영상을 자동으로 검색합니다. 다른 위치의 원본 영상은 **파일 → 현재 사고에 영상 추가**나 드래그앤드롭으로 추가합니다. 기관은 `samsung`으로, 파일명의 13자리 숫자는 사고 구분 번호로 자동 입력됩니다.
2. `1234567890123.mp4`, `1234567890123_1.mp4`, `1234567890123_2.mp4`처럼 같은 사고번호를 가진 영상은 한 사고에 묶이고, 기본 영상과 뒤쪽 번호 순서로 정렬됩니다. 파일 메뉴의 **현재 사고에 영상 추가**나 드래그앤드롭으로 개별 영상을 직접 연결할 수도 있습니다.
3. 왼쪽 사고 항목을 위·아래로 드래그하면 표시 순서가 바뀌며, 변경된 순서는 작업 DB에 저장됩니다.
4. 중앙 영상 플레이어 아래 컨트롤이나 단축키로 필요한 프레임을 찾습니다. 플레이어 상단의 회전 아이콘을 누를 때마다 현재 영상이 시계 방향으로 90°씩 회전하며, 0° → 90° → 180° → 270° 순서로 순환합니다.
5. **T 지정**, **충돌 지정**으로 조사 기준 시점을 기록합니다. 다른 프레임을 지정하면 기존 시점이 교체되고, 같은 프레임에서 다시 누르면 해당 마커가 해제됩니다. 타임라인의 `T` 또는 `C` 마크를 클릭하면 해당 프레임으로 이동하며, 마우스를 올리면 강조색·포인터 커서·프레임 안내가 표시됩니다.
6. 우측 식별 영역과 9개 탭의 조사 항목을 입력합니다. **비고** 탭에는 글자 수 제한 없이 사고 추가정보를 입력할 수 있습니다.
7. 오른쪽 조사 패널 하단에서 **임시저장**, 검증을 통과한 뒤에는 **완료**를 누릅니다.
8. **다음**으로 다음 미완료 사고로 이동하고, 마지막에 **조사 결과 CSV 내보내기**를 사용합니다.

왼쪽 목록에서 사고나 개별 영상을 선택하면 **사고 삭제** 또는 **영상 삭제** 버튼이 표시됩니다. 삭제 전 확인을 거치며, 영상을 목록에서 삭제해도 디스크의 원본 영상 파일은 삭제하지 않습니다. 삭제한 영상은 작업 폴더를 다시 열어도 자동 복원되지 않으며, **현재 사고에 영상 추가**를 명시적으로 사용하면 다시 연결할 수 있습니다.

빈 작업 폴더는 사고 `0건`으로 시작하며 `SAMSUNG-001`을 자동 생성하지 않습니다. **새 사고**를 눌렀을 때만 수동 입력용 사고를 만들고, 마지막 사고도 실제로 삭제할 수 있습니다. 이전 버전에서 `SAMSUNG-001`에 잘못 연결된 13자리 파일명 영상은 작업 폴더를 열 때 파일명의 사고번호로 자동 이관하며 영상별 마커도 함께 보존합니다.

화면에 표시되는 프레임 번호는 사람이 읽기 쉬운 1부터 시작하고, DB와 CSV의 마커 프레임은 영상 처리 호환을 위해 0부터 시작합니다.

## 트리거 시점 속도 추정

플레이어 아래의 **속도 지점** 또는 **M**으로 현재 프레임에 기준 지점을 추가합니다. 차량이 도로의 기준물을 지나는 순간을 골라, **같은 차량 기준점**으로 측정하세요. 같은 프레임에서 다시 누르면 그 지점이 해제됩니다. 지점을 추가하면 측정 패널이 열리며 계기판 아이콘으로 접거나 펼칠 수 있습니다.

1. 첫 지점은 시작점입니다. 두 번째 지점부터 **이전 지점부터 거리(m)**에 실제 기준물 사이 거리를 입력합니다. 뒤에 추가하는 지점은 직전에 사용한 거리를 편의상 복사하므로, 각 구간의 실제 거리와 일치하는지 확인하세요. 도로 표식 길이를 자동으로 가정하거나 영상을 자동 분석해 거리를 구하지는 않습니다.
2. 각 구간의 평균 속도는 `거리 ÷ (프레임 차 / 실제 FPS) × 3.6`으로 표시합니다.
3. **T 지정**을 하면 T 시점 속도를 계산합니다. 가까운 지점 최대 4개로 등가속도 위치 모형을 근사하며, 두 지점만 있으면 구간 평균을 사용합니다. 모형의 가속도 변화가 지나치게 크면 가까운 구간 평균으로 대체하고 경고합니다. 거리가 누락된 구간은 서로 연결하지 않습니다.
4. 그래프에는 구간 평균, T 근사선·추정값, 속도 구분 경계를 표시합니다. 타임라인의 번호, 표의 프레임·시각, 그래프의 지점 번호를 누르면 해당 프레임으로 이동합니다. **선택 삭제**, 확인 후 **모두 삭제**도 가능합니다.
5. **차량 속도에 적용**을 눌렀을 때만 트리거 탭의 속도 구분과 출처를 ‘사고영상’으로 입력합니다. 기존 EDR/보고서 출처를 바꾸거나 외삽·불안정한 추정값을 적용할 때는 확인을 받습니다. 사용자 정의 선택지의 저장값도 반영합니다.

실제 FPS를 확인할 수 없으면 재생용 대체 FPS로 속도를 계산하지 않습니다. 계산은 일정한 프레임 간격을 가정하므로 가변 FPS 영상에서는 정확한 시간 정보가 별도로 필요할 수 있습니다. 표시 범위는 **각 지점 ±0.5프레임 배치 가정의 민감도**이며, 거리 오차·모델 오차를 포함한 신뢰구간이나 감정 결과가 아닙니다. T가 측정 범위 밖이거나 지점이 지나치게 가까우면 경고를 확인하고 기준물을 다시 점검하세요.

측정 지점과 거리는 **영상별로** DB의 기존 마커 안에 선택 항목 `speed_points`로 저장되며 재실행 후 복원됩니다. 추정 수치는 영상을 열 때 실제 FPS로 다시 계산합니다. 기존 DB·JSON을 읽을 수 있고 조사 CSV의 칼럼 순서도 유지합니다. CSV의 `video_markers` JSON 안에 속도 지점을 포함하며, 구버전 앱에서 다시 저장하면 새 속도 지점 정보가 보존되지 않을 수 있습니다. 원본 영상은 변경하지 않습니다.

좁은 창에서는 프레임·마커 버튼을 두 줄로, 측정 표와 그래프를 세로로 배치합니다. 측정 패널 내부만 스크롤하므로 조사 입력 사이드바를 침범하지 않습니다.

## 구간 객체 검출과 관여 객체 라벨링

영상 전체가 아니라 **필요한 시점만** 검출합니다. 플레이어 아래 검출 아이콘(▣)으로 **객체 검출 · 라벨링** 패널을 엽니다.

1. **분석 구간**의 시작/끝 프레임(1부터, 끝 포함)을 직접 입력하거나 **현재 프레임을 시작으로 지정 / 현재 프레임을 끝으로 지정**, **T~C**(트리거~충돌 마커)를 사용합니다. 시작과 끝을 같게 하면 한 프레임만 검출합니다. 재생·탐색은 입력한 구간을 바꾸지 않습니다. 타임라인에서 **Shift+드래그**해도 구간이 선택되며, 선택 구간은 타임라인에 띠로 표시됩니다. **간격**은 구간 안에서 몇 프레임마다 처리할지 정합니다.
2. 트리거·충돌 역할을 고르지 않고 **공통 객체**로 한 번만 검출합니다. 같은 결과를 `[객체]`·`[충돌]` 양쪽 탭에 각각 반영할 수 있으며, 검출만으로 조사값을 자동 변경하지 않습니다. 기존 저장 객체의 역할 정보는 보존합니다.
3. **검출 클래스**는 트리거·충돌 관여 객체 합집합을 기반으로 한 **21개 검출 분류·28개 프롬프트**입니다. 차량, 이륜·PM, 자전거, 보행자와 기존 시설물·건물/조경·기타 17종을 검출합니다. `investigator/assets/detection_taxonomy.json`에서 고정 키·프롬프트·허용 세분류·추천값을 관리하며, **조사 양식의 선택지 편집과 독립적**입니다.
4. **검출 실행**은 별도 프로세스에서 **Grounding DINO**를 실행합니다. 취소·실패 시 기존 결과는 유지합니다. 성공 결과는 대상 사고의 `investigations.db`에 자동 저장하며, 다른 사고의 미저장 변경은 저장하지 않습니다. 검출은 선택 기능이므로 검출·라벨 편집만으로 조사 완료 상태를 해제하지 않습니다. 저장 실패 시 경고를 확인한 뒤 임시저장으로 다시 저장하세요.
5. 프레임 간 같은 **대분류** 객체를 기존 위치·크기 규칙으로 연결합니다. `V001`(차량)·`M`(이륜·PM)·`B`(자전거)·`P`(보행자)·`R`(시설·건물)·`A`(동물)·`D`(낙하물) ID를 사용하며, 직접 그린 객체는 `U001`부터입니다. 검출 박스의 위치·크기 기반 연결이며 별도의 영상 메모리 추적 모델을 사용하지 않습니다.

표에서 객체를 선택(영상 위 박스를 클릭해도 선택)한 뒤 아래 줄에서 편집합니다.

- **세분류**는 해당 검출 대분류의 고정 선택지만 표시합니다. 차량은 `car→승용`, `van/bus→승합`, `truck→화물`, `excavator→특수`로 추천하며 이륜·PM은 이륜이 기본입니다. 보행자는 어린이/어른을 직접 선택해야 합니다. 특수차량의 굴착기/견인차/소방차/구급차 상세는 선택 입력입니다. 역할·조사 양식 이름을 바꿔도 검출 세분류는 바뀌지 않습니다.
- **동일 ID 전체 프레임에 적용**은 기본 체크입니다. 해제하면 현재 프레임만 수정합니다. 한 ID 안에 여러 세분류(미지정 포함)가 있으면 `혼합`으로 표시하고 조사 반영을 막습니다. 전체 프레임을 같은 세분류로 통일하거나 **현재 프레임을 새 ID로 분리**해 정리하세요.
- **확인**: 세분류 변경과 별도로 검수 완료를 표시합니다. 세분류를 실제로 수정하면 해당 범위의 검수가 해제됩니다. 재검출 시 사용자 수정·검수한 주석과 직접 그린 박스는 보존합니다.
- **사각형 그리기**를 켜고 영상 위를 드래그하면 현재 프레임에 공통 객체를 직접 추가합니다. **객체 삭제**는 선택 객체의 모든 프레임 박스를 삭제합니다. 한 프레임만 삭제하는 별도 기능은 제공하지 않습니다.
- 영상 또는 검출 패널에서 **Ctrl+Z**로 박스 편집을 실행 취소하고, **Ctrl+Y / Ctrl+Shift+Z**로 다시 실행합니다. 객체 추가·삭제와 세분류·확인 상태 편집이 대상이며, 입력창에서는 기존 텍스트 실행 취소를 유지합니다. 그리는 도중 Ctrl+Z를 누르면 작성 중인 사각형만 취소합니다. 기록은 실행 중 사고·영상별로 분리하고 메모리 사용을 제한하며 앱 재실행 시에는 복원하지 않습니다. 새 자동 검출 결과를 받아들이면 그 대상 영상의 편집 기록을 초기화합니다. 조사 탭에 이미 반영한 값은 박스 실행 취소로 되돌리지 않습니다.
- **표시 신뢰도 ≥**에서 0.00~1.00 범위를 조절합니다(기본 0.50, 재실행 시 설정 유지). 영상 박스와 표 모두 프레임별 신뢰도로 즉시 필터링하며, 원본 검출 결과를 삭제하지 않습니다. 값을 낮추면 다시 표시됩니다. 직접 그린 박스와 신뢰도가 없는 박스는 항상 표시합니다. 재검출 문턱값이나 조사 탭의 기존 값을 변경하는 기능은 아닙니다.
- **검출 객체 표**는 표시하는 객체 수에 맞춰 높이가 늘거나 줄어듭니다. **현재 프레임만** 필터에도 반응합니다. 100행을 넘으면 표 내부 스크롤을 사용해 과도하게 큰 위젯이 생기지 않도록 합니다. 영상에서 박스를 클릭할 때는 선택 행만 갱신하며 전체 표를 다시 만들지 않습니다.
- **객체 탭에 반영 / 충돌 탭에 반영**만 명시적으로 조사값을 추가합니다. 공통 객체는 양쪽 반영 대상입니다. 혼합 ID·미지정 세분류·연결할 수 없는 선택지가 있으면 해당 탭의 전체 반영을 중단합니다. PM은 검출·라벨링할 수 있지만 기본 `[객체]`에는 PM 선택지가 없으므로 경고하고 반영하지 않습니다(`[충돌]`에는 반영 가능). 기존 조사 선택은 자동 삭제하지 않으며 재분류 후 재반영도 추가 방식입니다. 객체 탭 반영 시 장애물 유무는 ‘유’로 설정합니다.

속도 측정·객체 검출 패널 위의 가로 스플리터를 드래그하면 영상/재생바 영역과 도구 패널의 높이를 조절할 수 있습니다. 각 도구의 높이는 실행 중 별도로 기억하며, 도구를 닫으면 영상이 빈 영역을 사용합니다.

검출 객체는 영상별 선택 데이터 `objects_by_video`로 별도 관리합니다. 모델 대분류·프레임별 원본 프롬프트·추천 세분류·사용자 세분류·검수·프레임 예외를 분리 저장하며, 원본 영상은 수정하지 않습니다. **검출 원시 정보는 조사 통계·CSV·Word에 자동 포함하지 않습니다.** 명시적으로 조사 탭에 반영한 값만 기존 조사 출력으로 전달됩니다. 객체 데이터가 없는 사고에는 선택 항목을 추가하지 않습니다.

구형 객체 데이터는 읽을 때 v2로 변환하며 좌표·ID·사용자 수정·검수 상태를 보존합니다. 과거에 저장되지 않은 원본 프롬프트는 `null`입니다. 처음 새 객체 형식을 저장할 때 `.backups/investigations.pre-object-v2-*.db`에 변경 전 백업을 만들고 프로젝트 payload 버전을 3으로 올려 구버전의 재저장에 의한 정보 유실을 막습니다. 구버전 AVAT로 되돌리려면 이 백업을 별도 폴더로 복원하세요. 읽기만 할 때 전체 사고를 재저장하지 않습니다.

### 검출 환경 준비

현재 실행·배포 대상과 새 설정의 기본값은 **Grounding DINO**입니다. 기존 YOLOE·SAM3·EfficientSAM3 구현과 테스트, 로컬 가중치 및 호환용 선택지는 보존하지만 이번 설치·배포 구성에 포함하지 않습니다. 기존 사용자 설정을 강제로 덮어쓰지는 않으므로 다른 모델을 저장한 PC에서는 **설정 → 객체 검출 환경…**에서 Grounding DINO로 변경해야 합니다.

AVAT 본체와 검출은 **하나의 독립 Python 환경에 함께 설치**합니다. 실행용 `requirements.txt`는 PySide6·OpenCV·NumPy와 PyTorch·Torchvision·Transformers·Pillow 및 전이 의존성을 설치합니다. NumPy **2.1.3**, Pillow **11.1.0**, OpenCV **4.11.0.86** 조합을 유지합니다. Ultralytics·CLIP·MobileCLIP 및 다른 모델의 연구 소스나 변환 도구는 Grounding DINO 실행에 필요하지 않습니다. 설치 명령은 위 **설치 및 실행**과 같습니다.

패키지 설치의 `python -m pip install ".[detection]"`도 같은 Grounding DINO 의존성을 사용합니다. 자동 검출 없이 재생·조사·수동 박스 편집만 쓰는 PC는 `python -m pip install -e .`로 본체 의존성(PySide6·OpenCV·NumPy)만 설치할 수 있습니다.

검출은 UI 응답성과 오류 격리를 위해 별도 **프로세스**(소스 실행: `<Python> -m investigator.detection_worker`, EXE: `AVAT.exe --avat-worker investigator.detection_worker`)에서 실행하지만 별도 가상환경은 필요하지 않습니다. 실행용 라이브러리는 앱을 실행하는 `.venv`에 모두 설치합니다. 검출용 Python은 앱의 사용자 설정, 프로그램 폴더의 `detection-runtime.json`, 앱을 실행한 Python 순서로 정합니다. `detection-runtime.json`의 `python` 항목은 선택 사항이며, 생략하거나 빈 문자열로 두면 AVAT를 실행한 Python(EXE 배포본은 `AVAT.exe`의 내장 환경)을 사용합니다. 이전에 저장한 설정이 파일보다 우선할 수 있으므로 **설정 → 객체 검출 환경…**에서 Grounding DINO와 새 환경의 Python·모델 경로를 확인하세요.

### Grounding DINO 오프라인 설정과 모델

프로그램 폴더의 `detection-runtime.example.json`을 `detection-runtime.json`으로 복사해 사용합니다. 기본 예시는 다음과 같습니다.

```json
{
  "version": 1,
  "backend": "grounding_dino",
  "python": ".venv/Scripts/python.exe",
  "model": "runtime/models/grounding-dino-base",
  "device": "auto",
  "offline": true
}
```

상대 경로는 이 JSON 파일이 있는 폴더 기준입니다. 소스 실행에서는 저장소 루트, EXE 배포본에서는 `AVAT.exe`가 있는 폴더가 프로그램 폴더입니다. EXE 배포본의 `detection-runtime.json`(원본 `packaging/detection-runtime.json`)은 `python`을 생략해 내장 환경을 사용합니다. Git에 포함되지 않는 실제 설정 파일과 로컬 가중치는 새 PC에서 별도로 준비합니다. `device: "auto"`는 사용 가능한 장치를 선택하며 CPU 추론도 가능하지만 느릴 수 있습니다. CUDA 사용 시에는 대상 드라이버와 호환되는 PyTorch 휠을 준비해야 합니다.

`runtime/models/grounding-dino-base/`에는 다음 **7개 파일**을 함께 둡니다. 현재 로컬 파일 합계는 약 **934MB(891MiB)**이며 `model.safetensors` 하나만 복사해서는 실행할 수 없습니다.

- `config.json`
- `model.safetensors`
- `preprocessor_config.json`
- `special_tokens_map.json`
- `tokenizer.json`
- `tokenizer_config.json`
- `vocab.txt`

모델 출처는 `IDEA-Research/grounding-dino-base`입니다. 모델 폴더의 다운로드용 `.cache/`는 실행에 필요하지 않습니다. 로컬 모델 폴더와 `offline: true`를 사용하면 로컬 파일만 읽으며 실행 중 모델 다운로드를 시도하지 않습니다. 파일이 누락되면 미리 보완해야 하며 온라인 모델 ID로 대체하지 않습니다.

**설정 → 객체 검출 환경…**에서 Python·로컬 모델 경로·오프라인 실행을 확인합니다. 청크 크기(기본 8), 박스 임계값(0.30), 텍스트 임계값(0.25), CUDA FP16 사용 여부도 조정할 수 있습니다. 대분류별 프롬프트는 같은 청크에 유지하며 한 대분류의 프롬프트가 청크 크기보다 많으면 해당 청크만 설정 크기를 초과할 수 있습니다. Grounding DINO는 **박스 전용**이므로 마스크를 만들지 않습니다. 기존 클래스별 임계값, 중복 제거, 위치 기반 추적, 검수 절차는 유지하며 매핑할 수 없는 라벨은 결과 JSON의 `mapping_failures`와 로그에 보존합니다.

검출은 보조 수단이므로 라벨은 반드시 사람이 확인하세요. 작은 시설물과 화단·흙더미·도로낙하물은 누락·오검출이 있을 수 있습니다. 구간 내 프레임을 읽지 못하면 이번 검출을 실패 처리하고 기존 라벨을 유지합니다. 빌드한 EXE의 Grounding DINO 실제 추론은 빌드 서버에서 인터넷을 차단하고 CPU로 확인했습니다. RTX 5080 GPU 추론과 실제 폐쇄망 대상 PC의 동작은 아래 [검증 결과와 남은 확인 사항](#검증-결과와-남은-확인-사항)과 같이 대상 PC에서 확인해야 합니다.

### 기존 개발 환경을 재사용할 때

2026-10-23 확인한 과거 `.venv-yoloe`는 삭제된 환경의 패키지를 참조해 `torch`·`cv2`를 찾지 못했습니다. 현재 루트 환경에도 PyTorch가 준비되어 있지 않으므로 **설정 변경만으로 검출이 실행되는 상태는 아닙니다.** 이 연결형 환경을 복사하거나 이름만 바꾸지 말고 위 설치 절차로 독립 `.venv`를 만드세요. 기존 가상환경·다른 모델 가중치는 이번 정리에서 삭제하지 않습니다.

## 통계 분석

상단 **조사 / 통계** 전환으로 통계 화면을 엽니다. 현재 프로젝트의 실제 조사 값을 사용하며, 기본 집계 대상은 **완료** 사고입니다. 임시저장 사고를 포함하거나 사고일자 기간, 조사 항목별 조건을 추가할 수 있습니다. 조건 칩 사이는 기본 **그리고 (AND)**이고, 칩 왼쪽 체크박스로 개별 조건을 2개 이상 선택한 뒤 **또는으로 묶기**를 누르면 그 조건들만 **또는 (OR)**으로 결합합니다. 묶음은 한 단계만 허용하며 우클릭의 **묶음 풀기**로 다시 개별 AND 조건으로 바꿉니다. 완료 상태·기간은 묶음과 관계없이 적용하고, 여러 조건에 해당하는 같은 사고는 한 번만 집계합니다. 추가 조건이 없으면 상태·기간에 맞는 전체 사고를 표시합니다. 아직 저장하지 않은 입력도 화면 집계에 반영되지만 통계 탭을 여는 것만으로 완료 처리하거나 저장 데이터를 변경하지는 않습니다.

**+ 조건 추가**는 검색 가능한 변수 선택과 값 체크리스트가 있는 팝오버를 엽니다. 각 값 옆 건수는 현재 상태·기간·추가 조건에 해당하는 사고를 기준으로 표시하며, 수정 중인 조건도 집계 기준에 포함합니다. 사고가 없는 선택지도 0건으로 보여 주며 텍스트 항목은 실제 저장된 값을 표시합니다. 값 검색과 **전체선택 / 선택해제**는 현재 검색 결과에 적용합니다. 한 조건 안에서 체크한 값은 OR이며, **제외**는 선택한 어느 값에도 해당하지 않는 사고를 뜻합니다. **(미입력)**도 선택할 수 있고, 전체선택 후 **(미입력)**만 빼면 입력된 값을 선택합니다. **적용**할 때만 조건이 바뀌며 취소하거나 바깥을 클릭하면 변경하지 않습니다. 칩 본문은 수정, 오른쪽 **×**는 삭제입니다. 묶음 칩 본문을 누르면 수정할 개별 조건을 고릅니다.

수치형은 **최소 (이상) ~ 최대 (미만)** 입력칸과 단위를 표시합니다. 최소는 포함하고 최대는 포함하지 않으며, 빈 칸은 해당 방향을 제한하지 않습니다. 예를 들어 운전 경력 `10 이상`, 주행거리 `10000 이상 ~ 50000 미만`을 설정할 수 있습니다. 잘못된 숫자나 역순·빈 구간은 적용 전에 안내합니다. **(미입력)만**으로 누락된 수치를 선택할 수 있습니다. 숫자 범위를 제외하면 그 범위에 해당하지 않는 사고(미입력 포함)를 선택합니다. 이전 조건 형식은 불러올 때 호환 처리합니다.

- **개요**: 사고 수, 인명피해 사고 수, 평균 트리거→충돌 시간, 필수 미입력 사고 수와 고정한 항목의 분포를 확인합니다.
- **항목 분석**: 항목 검색·입력률, 건수·비율·표 보기, 막대 가로/세로 전환을 제공합니다. 명목 단일 선택의 표시 범주가 5개 이하일 때는 클릭 가능한 파이(도넛) 보기도 제공합니다. 숫자 구간 분포와 평균·중앙값·사분위수를 확인하며, 사용자 정의 탭·항목과 수정한 선택지 이름도 반영합니다. 항목을 개요에 고정하거나 해제할 수 있습니다.
- **교차 분석**: 항목 유형에 따라 자동으로 보기를 바꿉니다. 범주×범주는 히트맵 또는 100% 누적 막대, 범주×수치는 상자수염과 개별 사고 점, 수치×수치는 산점도와 최소제곱 추세선입니다. 예시 조합·행열 바꾸기·같은 항목 선택 안내와 실제 사고 드릴다운을 제공합니다. 열이 다중 선택이면 사고 비율이 100%를 넘을 수 있어 누적 막대 대신 히트맵을 사용합니다. 각 축 100개 범주 또는 2,500칸을 넘는 교차표와 100개를 넘는 상자 그룹은 필터로 범위를 줄이도록 안내하며 임의로 일부 값만 집계하지 않습니다.
- **나비형 비교**: 교차 분석에서 선택합니다. 가운데 축의 분포를 왼쪽 파란색·오른쪽 주황색 막대로 비교하며, 두 그룹 또는 한 그룹 vs 나머지, 그룹 내 비율(기본) 또는 건수로 전환할 수 있습니다. 각 그룹의 선택 상자 전체를 누르면 검색·현재 필터 기준 건수·전체선택/선택해제를 제공하는 체크박스 팝오버가 열립니다. 여러 값을 체크하면 **OR 합집합**으로 묶고 같은 사고는 그룹 내 한 번만 셉니다. ‘나머지’는 왼쪽 그룹에 속하지 않는 유효 사고 전체이며, 두 그룹에서 같은 선택지를 동시에 고를 수는 없습니다. 좌우는 동일한 눈금을 쓰고 분모는 각 그룹의 사고 수입니다. 수치 항목은 공통 구간으로 나누고 운전 연령 등은 기존 순서를 유지합니다. 그룹 미입력·오류·비해당은 제외하며, 다중 선택 그룹의 사고 중복과 20건 미만 그룹을 안내합니다. 막대에 마우스를 올리면 건수·비율·분모가 표시되고, 누르면 해당 그룹의 실제 사고, 가운데 구간을 누르면 좌우 사고를 중복 없이 확인합니다. 선택 구간과 가장 큰 비율 차이를 표시하며 PNG·CSV 내보내기도 지원합니다. 비교 설정은 실행 중 프로젝트 탭별로 유지됩니다.
- **영상 지표**: 연결된 모든 영상의 T·C 지정률과, 사고별 현재 선택 영상의 시간 차를 집계합니다. 시간은 `(충돌 프레임 - 트리거 프레임) / 실제 FPS`로 계산합니다. FPS 미확인·마커 누락·역순 영상은 시간 계산에서 제외하며, 재생용 대체 FPS를 통계에 사용하지 않습니다. 영상 정보 확인은 별도 스레드에서 수행하며 원본 파일을 수정하지 않습니다.
- **데이터 품질**: 상태 필터와 무관하게 전체 작업 상태를 확인합니다. 기간·추가 조건은 적용합니다. 조건부 필수 항목별 실제 해당 건수·입력률·미입력·오류를 표시하며, 선택 항목과 조건상 해당 없는 항목은 필수 미입력 집계에서 제외합니다. 문제 사고를 누르면 조사 화면의 확인할 항목으로 이동합니다.

교차 분석의 **읽는 법**은 관측 분포와 참고용 검정 결과를 함께 보여 줍니다. 범주×범주는 Pearson 카이제곱(연속성 보정 없음)·크라메르 V, 범주×수치는 동순위 보정 크러스컬–월리스, 수치×수치는 Pearson 상관·양측 p값을 사용합니다. 카이제곱은 유효 20건 미만, 크러스컬–월리스는 그룹별 5건 미만, 상관은 유효 쌍 3건 미만이면 검정을 제한합니다. 미입력·형식 오류·비해당은 검정에서 제외하고, 그룹에 같은 사고가 중복되면 독립 표본 검정을 하지 않습니다. 희소한 기대 빈도·상수 값 등은 별도로 안내합니다. 검정과 추세선은 인과관계나 감정 결과를 뜻하지 않습니다.

연속 수치인 **T 시점 추정 속도(km/h)**는 현재 선택 영상에 저장된 속도 지점·거리·T와 실제 FPS로 다시 계산합니다. 기존의 정차·크립·저속·중속·고속 구분을 임의의 수치로 변환하지 않습니다. 측정값 또는 실제 FPS가 없으면 수치 속도를 포함한 분석에서 제외하며, 기존 조사 값은 바꾸지 않습니다. 상자그림 그룹과 산점도 점은 유효 수치가 있는 사고만 보여 주므로, 해당 드릴다운은 필터 고정 없이 조사 열기만 제공합니다.

막대·표의 칸을 누르면 오른쪽에 해당 사고 목록이 표시됩니다. 사고를 눌러 조사 화면으로 이동하거나 **이 조건을 필터로 고정**할 수 있습니다. 그래프 조건을 고정하면 기존 묶음을 유지한 채 선택 조건을 추가로 모두 만족하도록 좁힙니다. 교차표의 두 축 조건도 각각 AND 칩으로 추가합니다. 다중 선택은 항목마다 사고를 한 번씩 세므로 비율의 합이 100%를 넘을 수 있습니다. 비율 분모와 미입력·해당 없음 수를 함께 표시합니다. 그래프의 자동 숫자 구간과 새 조건의 숫자 범위는 모두 이상·미만 기준입니다.

**내보내기**에서 현재 보기의 그래프/표 이미지(PNG), 전체 집계 표(CSV), 개요 요약과 고정 항목 표(PDF)를 저장합니다. PNG·PDF에는 필터와 집계 기준을 표시하며, 통계 CSV는 조사 결과 CSV와 별도의 집계용 파일입니다. 프로젝트별 통계 조건·고정 항목·보기는 실행 중 탭 전환 시 유지됩니다. 앱 재실행 시에는 기본 보기로 시작합니다.

화면은 제공된 통계 시안의 밝은 회색 배경, 흰색 카드, 절제된 파란색 강조와 공통 입력·버튼 스타일로 통일했습니다. 기존 조사 입력·재생·저장 방식과 CSV 스키마는 유지합니다. 추가 패키지 설치는 필요하지 않습니다.

## 사고 분석 보고서 내보내기

왼쪽 **사고 분석 보고서 내보내기** 또는 **파일 → 사고 분석 보고서 내보내기…**를 누릅니다.
선택 창에서 보고서로 만들 사고들을 체크한 뒤 **저장 폴더 선택…**으로 출력 위치를 지정합니다.
현재 목록에서 선택한 사고·영상의 부모 사고를 먼저 체크하며, 검색과 전체 선택/해제를 지원합니다.
현재 프로젝트의 사고만 대상으로 하고, 작성 중인 사고도 내보낼 수 있습니다.

**조건으로 사고 선택**에서 완료 상태·사고일자와 조사 항목별 조건을 설정하면 일치하는 사고만
자동으로 체크합니다. **+ 조사 항목 조건**으로 선택값 포함·미입력·숫자 범위 조건을 추가하고,
추가 조건은 **모두 충족(AND) / 하나라도 충족(OR)**으로 결합합니다. 상태와 기간은 어느 모드에서도
함께 적용합니다. 보고서용 조건 창은 변수별 라벨 드롭다운·숫자 비교 입력을 유지하며, 숫자 `사이`와 사고일자 기간은 양 끝을 포함합니다.
사용자 추가 항목과 수정된 선택지 이름·저장값도 현재 프로젝트의 양식 기준으로 판정합니다.
체크 후 개별 제외할 수 있고 **조건 일치 전체 선택**으로 다시 선택할 수 있습니다.
검색은 목록 표시만 바꾸므로 검색에서 숨겨진 체크 사고도 출력 대상에 포함됩니다.
조건 일치 사고가 없거나 날짜 범위가 잘못되면 내보내기를 비활성화하며, 사고 데이터는 변경하지 않습니다.

사고마다 `SAMSUNG-사고번호_사고분석보고서.docx`를 생성합니다. 같은 파일이 있으면 `_2`, `_3`을
붙여 기존 보고서를 보존합니다. 현재 입력 내용을 사용하되 조사 데이터의 저장·완료 상태는 바꾸지 않습니다.
미입력 텍스트는 `-`, 실제 숫자 0은 `0`으로 구분하고, 선택 항목은 Word 체크박스에 반영합니다.
사고일자는 `YYYY-MM-DD`, 시간은 `HH:MM`으로 표시하며 요일은 날짜로 계산합니다.

제공된 양식을 `investigator/assets/사고분석보고서.docx`에 포함했습니다. 38개 텍스트 변수와
85개 체크박스를 연결하며 표·글꼴·페이지 설정과 원본 양식은 보존합니다. Word가 설치되지 않은
컴퓨터에서도 내보낼 수 있고 추가 Python 패키지는 필요하지 않습니다.

양식의 `{{항목키}}`는 조사 항목의 안정적인 내부 키와 연결됩니다. 현재/기존 CSV 칼럼명도
지원하되 같은 이름이면 내부 키가 우선합니다. `{{incident_hour}}`는 `incident_time`의 별칭입니다.
예를 들어 `{{vehicle_fuel}}`는 사용연료, `{{vehicle_mileage}}`는 주행거리, `{{remarks}}`는 비고입니다.
체크박스 콘텐츠 컨트롤의 태그는 개별 CSV 칼럼명 또는 `CSV칼럼명|선택지`로 연결합니다.
조사 항목 편집에서 라벨·선택값·CSV명을 바꿔도 기존 항목의 연결은 유지합니다.
기본 양식에 칸이 없는 대표부상급수·영상 마커·사용자 추가 항목은 임의로 덧붙이지 않습니다.

입력 필드에 포커스가 있거나 통계 화면을 보고 있을 때는 재생 단축키가 입력을 가로채거나 숨겨진 영상을 재생하지 않습니다.

영상에 음성 트랙이 있으면 시스템 기본 출력 장치로 소리를 재생합니다. 일시정지·탐색·영상 전환 시 소리도 함께 제어하며, 음성 트랙이 없는 영상은 무음으로 재생합니다. 재생바 드래그 시 손잡이·요청 시각은 즉시 반영하고 영상은 비동기로 갱신합니다. 일시정지 중에는 오디오 탐색을 반복하지 않고, 재생을 시작할 때 최종 위치에 맞춥니다. 영상 디코딩은 별도 프로세스의 FFmpeg 자동 병렬 설정을 사용합니다.

오디오 백엔드의 초기화 안내와 영상 메타데이터 출력은 숨깁니다. 파일 시간 정보 경고나 디코딩 오류 등 경고·오류 로그는 유지합니다.

프로젝트 폴더의 자동 검색은 폴더 바로 아래에 있는 지원 영상 파일을 읽습니다. 이름이 `13자리 숫자` 또는 `13자리 숫자_1`, `_2` 형식이 아닌 영상은 건너뛰며, 같은 폴더를 다시 열어도 기존 사고와 영상은 중복 생성되지 않습니다.

열려 있는 프로젝트 폴더는 `QFileSystemWatcher`로 감시합니다. 폴더 바로 아래에 새 영상이 생기면 크기·수정 시간이 2초 동안 안정되고 읽을 수 있는지 확인한 뒤, 기존 13자리 사고번호 규칙에 따라 자동으로 추가·저장합니다. 하위 폴더는 감시하지 않으며, 파일 복사가 잠시 멈춘 경우에는 이 안정화 시간만으로 복사 완료를 확정할 수 없습니다. 기존 영상 파일을 삭제해도 조사 기록을 자동 삭제하지는 않습니다. 목록에서 직접 삭제한 영상·사고의 제외 설정은 자동 갱신에도 적용합니다.

현재 프로젝트의 자동 갱신은 수정한 목록 행과 새 사고만 반영하고 입력 중인 값·선택 사고·영상 재생 위치를 유지합니다. 다른 프로젝트 탭에서 새 영상이 감지되면 탭 이름에 `•`가 표시되고 해당 탭으로 이동할 때 반영합니다. 저장·복사·대화상자 처리 중에는 갱신을 보류하며, 저장 실패 시 입력값을 유지하고 잠시 후 다시 시도합니다.

**현재 사고에 영상 추가**, 영상 드래그앤드롭으로 가져올 때 나타나는 옵션에서 **작업 폴더로 복사**를 선택할 수 있습니다. 기본값은 선택하지 않은 연결형입니다. 선택하면 원본은 그대로 두고 현재 프로젝트 폴더에 파일을 복사한 뒤 복사본을 연결합니다. 개별 추가는 일반 파일명도 지원합니다. 같은 이름의 내용이 다른 파일은 순번을 붙이며, 13자리 사고번호는 유지합니다. 기존 파일과 내용이 같으면 해당 파일을 재사용합니다. 복사는 임시 파일에 완료한 뒤 최종 이름으로 반영하고, 복사·조사 데이터 저장 실패 시 이번에 생성한 복사본을 정리합니다. 복사 작업은 별도 작업 스레드에서 수행합니다.

## 저장 형식과 완료 기준

**설정 → 조사 항목 편집…** 또는 사고 조사 입력 제목 옆 편집 버튼에서 현재 작업 폴더의 양식을 변경할 수 있습니다.
왼쪽에서 탭·항목을 선택해 탭 제목/라벨, 항목 이름, CSV 칼럼명, 입력 방식, 필수 여부, 선택지와 기본값을 편집합니다.
**탭 추가**, **항목 추가**로 양식을 확장하고 **양식 적용 및 저장**을 누르면 즉시 화면에 반영됩니다. 취소하면 적용되지 않습니다.
왼쪽에서 탭 또는 항목을 선택하고 **▲ / ▼**로 순서를 변경할 수 있습니다. 항목은 해당 탭 안에서 이동하며, 상단 식별 구분 영역은 고정됩니다.
사용자가 추가한 항목·탭은 **선택한 항목 / 탭 삭제**로 양식에서 제외할 수 있습니다. 기본 항목·탭은 삭제할 수 없습니다. 삭제 결과는 **양식 적용 및 저장**을 눌러야 반영되며, 다음 CSV부터 해당 칼럼이 제외됩니다. 기존 사고에 입력한 값 자체는 DB에 보존합니다.
식별 구분의 기본 배치는 기관코드와 사고 구분 번호가 나란히 표시되는 2열입니다. 편집창의 식별 구분 → 항목 배치에서 1열/2열을 선택할 수도 있습니다.
**초기 설정 복원**은 `investigations.db`의 `initial_form_definition` 설정에 별도로 보관한 기본 양식의 이름·입력 방식·기본값·순서·배치를 불러옵니다. 복원 기준은 양식을 편집해도 변경되지 않습니다. 기존 작업 폴더에는 이 버전의 기본 양식을 초기값으로 추가합니다.
**초기 설정 복원**을 누르면 확인창이 표시되며 기본 선택은 ‘아니요’입니다. ‘예’를 선택하면 편집창에서 복원 결과를 확인할 수 있고, **양식 적용 및 저장**으로 확정합니다. 취소하면 편집 중인 내용도 그대로 유지합니다. 추가한 탭·항목·선택지와 조사 값 및 CSV 별칭은 유지합니다. 기존 조사 값이 초기 입력 방식과 맞지 않으면 일반 양식 편집과 동일하게 적용을 막고 해당 항목을 안내합니다.
탭의 **항목 배치**에서 1열(세로) 또는 2열(좌우)을 선택합니다. 2열은 목록 순서대로 왼쪽 → 오른쪽으로 배치하며, 항목별 **한 행 전체 너비 사용**으로 특정 항목만 전체 너비를 사용할 수 있습니다.
충돌 탭은 충돌대상 → 피해정도 확인불가를 전체 너비로 표시하고, 경상·중상 부상급수/대표급수/인원 및 사망·물적피해 항목을 좌우에 배치합니다. 순서·배치는 작업 폴더에 저장되며 재실행 시 복원됩니다. CSV 조사 칼럼도 현재 탭 → 항목 → 선택지 순서로 내보냅니다. 날짜·요일도 예외 없이 현재 편집 순서를 따릅니다.
입력 방식은 드롭다운, 정수·소수, 한 줄·여러 줄 텍스트, 체크박스/다중 선택을 지원합니다. 선택지의 표시 이름과 저장값은 별개이며, 기본값은 저장값으로 입력합니다(다중 선택은 한 줄에 하나).

양식은 `investigations.db`의 `form_definition` 설정에 사고 데이터와 함께 저장되어 재실행 시 복원됩니다. 다른 작업 폴더에는 영향을 주지 않습니다.
기본값은 이후 생성하거나 가져오는 새 사고에만 적용하며 기존 사고나 사용자가 비운 값은 덮어쓰지 않습니다.
기존 값에 맞지 않는 입력 방식·선택지 변경은 적용되지 않습니다. 새 필수 조건 때문에 완료 조건을 충족하지 못하는 사고는 미완료로 전환되고 입력 내용은 유지됩니다.

호환성을 위해 내부 항목 식별자는 고정합니다. 항목과 선택지의 이전 CSV 칼럼명은 저장 데이터·기존 보고서 슬롯과의 연결용 별칭으로만 보관하고, CSV에는 현재 설정한 칼럼명만 출력합니다. 새 항목은 화면에 추가한 위치에 해당하는 칼럼으로 내보내며 **▲ / ▼**로 위치를 바꾸면 CSV에도 반영됩니다. 삭제된 항목·선택지의 칼럼과 과거에 저장된 칼럼 순서에만 남은 이름은 출력하지 않습니다.
빈 값은 기존과 같이 `null`로 출력합니다. 선택지의 저장값을 바꾸면 텍스트형 CSV에는 바꾼 저장값을 출력합니다. 기본 충돌 대상은 기존처럼 범주 접두어를 뺀 선택값을 `|`로 연결합니다. 개별 선택 여부 칼럼은 `1`/`null`을 유지합니다.
날짜·요일, 부상급수, 조건부 질문, 선택지별 CSV 분리 항목은 자동 계산에 필요한 입력 방식과 필수 규칙을 보호합니다. 선택지의 표시 이름·저장값·개별 CSV 칼럼은 편집할 수 있습니다. 저장값을 바꾸면 기존 조사 결과와 기본값의 선택도 함께 옮기며, 조건부 질문과 자동 계산은 유지됩니다. 기본 선택지 자체는 삭제할 수 없습니다.
저장값과 개별 CSV 칼럼명은 각각 사용자가 직접 편집합니다. **양식 적용 및 저장 → CSV 다시 내보내기**를 하면 기존 사고 전체에 변경 사항을 반영하며 사고별 재입력이 필요하지 않습니다. 저장값이 중복되거나 다른 선택지의 이전 저장값과 겹치면 적용을 막습니다. 현재 양식은 버전 5이며, 구버전 앱은 읽을 수 없습니다.
장애물(보행자)과 충돌 대상의 기본 선택지는 기존 ‘어른’을 유지합니다. 기본 저장값은 각각 `어른`, `pedestrian.adult`이며, 기본 개별 CSV 칼럼은 `obstacle_adult`입니다. 이전 수정본이 ‘어른, 청소년’과 `obstacle_adult,youth`로 자동 변경해 저장한 기본 양식도 열 때 복구하며 기존 선택을 유지합니다. 현재 버전에서 사용자가 직접 편집해 저장한 값은 재실행해도 유지합니다.
기존 JSON의 `schema_version: 1`·`2`를 모두 읽어 이전합니다. 새 SQLite DB에는 저장소 버전과 양식 버전을 별도로 보관합니다. JSON 전용 구버전 앱에서는 새 DB를 읽을 수 없습니다.

작업 폴더의 `investigations.db`에 사고별 조사 값, 표시 순서, 영상 경로, 영상별 타임라인 마커·회전 각도(0°/90°/180°/270°), draft/completed 상태를 저장합니다. 원본 영상은 DB에 복사하지 않습니다. 입력/마커 변경 시 해당 목록 행만 갱신하고, 저장 시 변경한 사고만 트랜잭션으로 반영합니다. 조사 양식 변경은 호환성 검증 때문에 전체 사고를 확인합니다.

기존 `investigations.json`이 있으면 첫 열기에서 임시 DB로 변환하고 무결성·내용을 검증한 뒤 활성화합니다. 원본 JSON은 수정·삭제하지 않으며 이후 저장은 DB에만 반영합니다. 이전 실패 시 원본을 보존하고 오류를 표시합니다. DB가 이미 존재하면 JSON보다 우선하며, DB 오류 시 오래된 JSON으로 자동 되돌아가지 않습니다. 구버전 앱으로 같은 폴더를 계속 편집하면 JSON과 DB 내용이 달라지므로 함께 사용하지 마세요.

저장·불러오기·CSV 내보내기·백업의 디스크 작업은 별도 스레드에서 순차 처리합니다. 임시저장 중 조사 입력은 계속할 수 있으며, 저장 요청 이후의 추가 수정은 미저장으로 남겨 다음 저장에 반영합니다. 완료는 검증과 저장이 모두 성공한 후 화면에 반영하며 실패 시 미완료 상태를 유지합니다.

**파일 → 조사 데이터 백업…**으로 실행 중에도 일관된 단일 `.db` 백업을 만들 수 있습니다. 복원하려면 앱을 닫고 백업을 새 로컬 폴더에 `investigations.db`라는 이름으로 복사한 뒤 그 폴더를 엽니다. 영상 경로는 별도로 유지해야 합니다. 실행 중 생길 수 있는 `-wal`·`-shm` 파일은 임의 삭제하지 말고, DB 파일만 탐색기에서 복사하는 대신 앱의 백업 메뉴를 사용하세요. 작업 DB는 로컬 디스크에서 단독 사용하며 NAS/동기화 폴더에서의 공동 편집은 지원하지 않습니다.

성능·오류 진단 로그는 기본 `%LOCALAPPDATA%/AVAT/logs`의 `avat.log`와 `avat-crash.log`에 남습니다. 작업 시간·건수·프로세스 메모리와 오류 발생 위치를 기록하며 조사 입력값은 기록하지 않습니다. 로그는 크기 제한과 회전을 적용합니다. 강제 종료의 원인은 로그로 별도 확인해야 하며 모든 종료 상황에서 로그 기록이 보장되지는 않습니다.

### 병렬 디코더 격리와 타임라인 응답

기본 재생은 FFmpeg 자동 병렬 디코딩으로 동작하며, 캡처의 열기·탐색·읽기·해제는 전용 자식 프로세스 하나가 순차 처리합니다. UI 스레드는 프레임 복원 작업을 기다리지 않습니다. 명령은 작은 JSON 메시지로, 영상은 단일 RGB 공유 메모리 버퍼로 전달합니다. 최초 영상 열기만 성공/실패와 메타데이터를 확정하기 위해 제한 시간 내 대기합니다.

탐색 요청은 진행 중 한 건과 최신 대기 한 건만 유지합니다. 드래그 중 지난 대기 위치는 최신 위치로 교체하고, 이미 시작한 디코딩을 강제로 취소하지 않습니다. 손잡이·시각·프레임 입력은 요청 위치를 즉시 표시하며 이전 프레임 결과가 와도 되돌아가지 않습니다. 마커는 요청 위치가 아니라 실제 표시된 프레임에 지정합니다. 최근 프레임은 64MiB 이내의 바이트 제한 캐시에 보관하고, 영상 전환 시 비웁니다. 캐시의 표시 위치와 디코더의 실제 커서는 별도로 관리합니다.

네이티브 디코더가 비정상 종료되거나 응답을 멈추면 조사 입력과 마지막 화면을 보존하고 디코더만 제한적으로 재시작합니다. 첫 종료에는 병렬 모드를 재시도하고, 같은 영상에서 반복되면 해당 영상만 단일 스레드 안전 모드로 전환하며 추가 실패 시 자동 복구를 중단합니다. 안전 모드 기록은 현재 앱 실행 동안만 유지합니다. 영상 전환·닫기 후의 과거 결과는 무시하며, 종료 시 자식 프로세스와 공유 메모리를 정리합니다. 추가 패키지는 필요하지 않습니다. 통계 메타데이터 조회용 짧은 캡처는 기존 단일 스레드 정책을 유지합니다.

연속 1프레임 전진은 바로 다음 프레임을 읽어 불필요한 `CAP_PROP_POS_FRAMES` 탐색을 줄입니다. 뒤로 이동하거나 다른 위치로 점프할 때는 기존처럼 탐색합니다. 탐색·읽기 실패 시 일시정지하고 내부 위치를 무효화하며, 재개 시 마지막 표시 프레임 다음 위치로 재정렬합니다. 종료 시에는 정상 창 닫기뿐 아니라 이벤트 루프 종료 경로에서도 디코더를 정리합니다.

현재 버전의 Qt 오디오 디코더와 OpenCV 디코더를 구분해 시험하려면 실행 전에 다음과 같이 설정합니다. 음소거가 아니라 QMediaPlayer 자체를 생성하지 않으며 원본 영상은 바꾸지 않습니다. 설정하지 않은 기본 실행에서는 소리가 재생됩니다.

Windows의 Qt FFmpeg 로그는 `ERROR` 이상만 출력합니다. `stream 0, timescale not set` 등을 포함한 네이티브 경고는 터미널에 표시하지 않지만 실제 오류·치명적 오류와 다른 Qt 경고는 유지합니다. 표준 오류 스트림을 가로채거나 FFmpeg 스레드에서 Python 로그 콜백을 실행하지 않으며 영상 파일과 재생 설정은 바꾸지 않습니다.

```powershell
$env:AVAT_DISABLE_AUDIO = "1"
python main.py
```

오디오를 다시 사용하려면 다음 실행 전에 `$env:AVAT_DISABLE_AUDIO = "0"`으로 설정하거나 환경변수를 해제합니다.

`async_lock` assert는 FFmpeg 프레임 스레드의 내부 불변식 실패입니다. 프로세스 분리는 OpenCV 디코더의 종료를 앱 전체에서 격리하는 조치이지 FFmpeg 내부 오류 자체를 수정하는 것은 아닙니다. Qt 오디오 디코더는 부모 프로세스에 남아 있으므로 모든 종류의 네이티브 오류를 격리한다는 뜻도 아닙니다. 오류는 상태 표시줄과 진단 로그에 남기며, 동일 증상이 남으면 원본 문제 영상·재현 조작·진단 로그로 추가 확인해야 합니다.

### 다른 PC에서 블루스크린·전원 꺼짐이 날 때

AVAT는 일반 사용자 모드 프로그램이라 Windows 커널을 직접 멈출 수 없습니다. 블루스크린은 드라이버(그래픽·오디오·저장장치·보안 프로그램)나 하드웨어 오류에서, 갑작스러운 전원 꺼짐은 과열·전원부 보호에서 발생합니다. 앱은 CPU·GPU 부하나 드라이버 호출로 그 계기가 될 수 있습니다. 영상 디코딩은 OpenCV와 Qt 오디오 모두 CPU만 사용하며(하드웨어 디코더 미사용), 디코더·검출 프로세스는 '보통 미만' 우선순위로 실행합니다. 앱이 GPU를 직접 쓰는 곳은 검출의 CUDA 추론뿐이며, 화면 표시는 Windows 기본 그리기 경로를 사용합니다.

`avat.log`에는 실행 시 Windows·Qt·OpenCV 버전(`runtime`), 영상 열기(해상도·코덱·디코더 스레드 수, `video_opened`), 재생 상태(`playback_state`), 디코더 오류·복구가 시간과 함께 남습니다. 파일명과 조사 값은 기록하지 않습니다. Windows 기록과 시각을 맞춰 보세요.

```powershell
# 41: 비정상 종료(BugcheckCode 0이면 블루스크린 없이 전원 차단), 1001: 블루스크린 코드, WHEA: 하드웨어 오류
Get-WinEvent -FilterHashtable @{LogName='System'; Id=41,1001,6008} -MaxEvents 20 | Format-List TimeCreated, Id, Message
Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-WHEA-Logger'} -MaxEvents 20 -ErrorAction SilentlyContinue
Get-ChildItem C:\Windows\Minidump
```

AVAT를 실행하지 않은 시간에도 발생하면 PC 문제입니다. 재생·탐색·검출 중에만 발생하면 부하를 줄여 비교합니다. 다음 설정은 실행 전에 지정하며 기본값은 바뀌지 않습니다.

```powershell
$env:AVAT_DECODER_THREADS = "2"   # 디코더 스레드 상한(기본: 코어 수, 최대 16). 탐색이 느려질 수 있음
$env:OMP_NUM_THREADS = "2"        # CPU 검출 시 PyTorch 스레드 상한
python main.py
```

다음 조건을 모두 만족해야 완료할 수 있습니다.

- 고정 식별 정보와 일반 필수 질문 입력
- 장소는 일반장소·특수장소·기타 텍스트 중 하나 이상 입력
- 장애물 `유`이면 객체 종류와 거동 상태 입력, 차량 장애물이 있으면 대면 상태 입력
- 피해 `확인 가능`이면 경상·중상·사망·물피 수치를 모두 입력 (`0`도 유효)
- 경상부상급수(12~14급)와 중상부상급수(1~11급)를 각각 쉼표로 입력하면 목록을 오름차순 정렬하고 해당 인원수를 자동 집계하며, 각 목록의 가장 낮은 급수를 경상·중상대표부상급수로 분리해 표시
- 날짜와 시간의 실제 형식 및 날짜-요일 일치
- 각 영상에서 트리거가 충돌 프레임보다 늦지 않음

완료한 사고를 다시 수정하면 안전을 위해 draft 상태로 돌아갑니다.

### 배포본에서 JSON 자동 이전 기능 제거

이전 완료 후 자동 이전 코드를 제외하려면 다음 두 단계만 수행합니다.

1. `investigator/storage.py`의 `_migrate_legacy()` 안에서 `from investigator.legacy_migration import migrate_legacy as migrator` 한 줄을 주석 처리합니다.
2. `investigator/legacy_migration.py` 파일을 삭제합니다.

나머지 저장소 함수는 유지합니다. 기존 DB 읽기·저장·백업 및 빈 폴더의 새 DB 생성은 정상 작동합니다. JSON만 있는 폴더는 이전 필요 안내와 함께 열기·저장·백업을 중단하여 기존 자료를 보호합니다. 기본 소스에서는 자동 이전이 활성화되어 있습니다.

## CSV 규칙

CSV 저장 위치를 선택하면 기존 조사 CSV와 `<CSV 파일명>_속도분석.csv`를 같은 폴더에 함께 저장합니다. **데이터 명세서(원본)도 함께 내보내기** 체크박스는 기본값이 선택이며, 해제해도 두 CSV는 저장합니다. 선택하면 앱에 포함된 원본 `investigator/assets/AVAT 데이터 명세서.xlsx`를 내용·서식 변경 없이 같은 폴더의 `<CSV 파일명>_데이터명세서.xlsx`로 저장합니다. 조사 항목의 순서·이름을 바꾸거나 항목을 추가·삭제해도 명세서는 바뀌지 않으며, 그런 변경은 조사 CSV에만 반영됩니다. 같은 이름의 속도 CSV나 명세서가 있으면 옵션 창에서 덮어쓰기를 안내합니다.

원본 명세서는 기본 양식 기준으로 메타데이터 7개, 조사 항목, 마지막 `report_accident_number`를 설명하며 별도 속도 분석 CSV 칼럼은 포함하지 않습니다. 명세서 내용을 바꾸려면 원본 파일을 직접 수정합니다.

- 요청서에 적힌 칼럼명은 오탈자와 대소문자까지 그대로 유지합니다. 예: `vehicle_milege`, `obstacle_Existence`, `incident_damage_Unknown`, `Lighting/Environmental_Condition`.
- 조사 CSV는 편집 화면의 탭 → 항목 → 선택지 순서를 따릅니다. 날짜·요일의 고정 순서 예외는 없으며, 기본 화면에서는 `incident_date`, `incident_day` 순서입니다. `▲ / ▼`로 순서를 바꾸어 저장하면 다음 내보내기와 앱 재실행 후에도 반영됩니다. 앞의 7개 워크플로 메타데이터와 마지막 `report_accident_number` 위치만 고정합니다.
- 옵션별 boolean 칼럼은 선택된 값만 `1`로 기록하고, 미선택·미입력·비적용 값은 `null`로 기록합니다. 사용자가 명시적으로 입력하거나 선택한 실제 값 `0`은 유지합니다.
- 한 칼럼에 들어가는 다중 선택은 스키마 순서대로 `|`로 연결합니다.
- `collision_target`은 요청서의 선택값 그대로 `승용|어른`처럼 내보냅니다.
- `active_video_file`, `trigger_frame`, `collision_frames`는 현재 선택 영상 기준이며, 모든 영상의 마커는 `video_markers` JSON에도 함께 보존합니다. 호환성을 위해 `collision_frames` 이름은 유지하지만 영상별 값은 최대 1개이며, 기존 다중 값은 가장 이른 충돌 시점 하나로 정규화합니다.
- 영상이나 마커가 지정되지 않은 워크플로 메타데이터 셀도 `null`로 기록하며, 실제 값 `0`은 그대로 보존합니다.
- 자유 텍스트가 스프레드시트 수식 문자로 시작하면 작은따옴표를 붙여 수식 실행을 방지합니다.
- 비고 탭의 사고 추가정보는 `remarks` 칼럼에 줄바꿈을 포함한 텍스트로 기록합니다.
- 마지막 칼럼 `report_accident_number`는 보고서에 사용하는 수정 사고번호이며 원래 `accident_classification`·`case_id` 값은 유지합니다. 13자리 원래 번호의 앞 8자리 날짜가 유효한 사고를 프로젝트 전체에서 숫자 오름차순으로 정렬하고, 날짜별로 `20200113_001`, `20200113_002`처럼 부여합니다. 수동 목록 순서나 보고서 선택 범위에는 영향을 받지 않으며, 보고서 파일명과 본문에도 같은 번호를 사용합니다(예: `SAMSUNG-20200113_001_사고분석보고서.docx`). 13자리/날짜 형식이 유효하지 않으면 새 CSV 칼럼은 `null`, 보고서는 원래 번호를 유지합니다.
- 수정 사고번호는 원본을 덮어쓰는 영구 식별자가 아니라 내보낼 때 계산하는 값입니다. 같은 날짜의 사고를 추가·삭제하거나 원래 번호를 수정하면 순번이 재계산됩니다. 보고서와 CSV를 비교할 때는 같은 프로젝트 구성으로 다시 내보내세요. 사용자 정의 보고서 양식에서는 `{{report_accident_number}}` 슬롯으로 새 번호를 사용할 수 있습니다.
- 요청서가 “기존 `site_*` 칼럼”의 정확한 이름을 제공하지 않아, 현 버전은 [스키마 코드](investigator/schema.py)의 중앙 매핑을 사용합니다. 실제 기존 데이터셋 헤더가 제공되면 `SITE_CHOICES`만 교체하면 됩니다.

### 속도 분석 CSV

예를 들어 `조사결과.csv`를 내보내면 `조사결과_속도분석.csv`도 자동 생성합니다. 사고에 연결된 **모든 영상**에서 실제 지정된 트리거(T)·충돌(C)·속도 지점마다 한 행을 기록합니다. 영상 안에서는 프레임순으로 정렬하며, 같은 프레임이 여러 역할이면 각각 기록합니다. 마커가 전혀 없으면 헤더만 생성합니다. 원본 영상·저장된 마커·기존 조사 CSV 칼럼은 바꾸지 않습니다.

| 칼럼 | 의미 |
| --- | --- |
| `case_id`, `accident_classification`, `report_accident_number` | 사고 표시 ID, 원래 사고번호, 기존 CSV·보고서와 동일한 수정 사고번호 |
| `video_file`, `video_name` | 영상 경로, 파일명 |
| `event_type`, `point_index` | `trigger` / `collision` / `speed_point`, 속도 지점 번호(1부터) |
| `frame_index`, `display_frame` | 내부 프레임(0부터), 화면에 표시되는 프레임(1부터) |
| `time_seconds`, `timecode`, `fps` | 영상 시작 기준 초, `HH:MM:SS.mmm` 시각, 실제 영상 메타데이터 FPS |
| `previous_point_frame_index`, `previous_point_time_seconds` | 바로 이전 속도 지점의 내부 프레임·초 |
| `distance_from_previous_m` | 이전 속도 지점부터 현재 지점까지 입력한 거리(m) |
| `segment_speed_kph` | 해당 구간의 평균 속도(km/h), 화면 속도 표와 같은 계산 |
| `trigger_speed_estimate_kph` | T 행에만 기록하는 기존 트리거 추정속도(km/h) |
| `estimate_method`, `estimate_warnings` | 계산 방식, `거리 미입력`·`FPS 미확인` 등 짧은 경고(있을 때만) |
| `missing_distance_points` | 거리가 입력되지 않은 속도 지점의 1부터 시작하는 정수 번호 목록(예: `[2, 3]`), 없으면 `null` |

거리 누락 번호는 트리거 행에서 해당 영상 전체의 목록, 각 속도 지점 행에서는 해당 지점 하나만 기록합니다. 첫 지점은 이전 거리 자체가 없는 시작점이므로 누락 목록에서 제외하며 충돌 행의 목록은 `null`입니다. `estimate_warnings`에는 긴 설명이나 `2번` 같은 표현 대신 짧은 경고만 기록합니다.

첫 속도 지점은 이전 거리·구간 평균 속도가 없으므로 `null`입니다. 충돌 행은 지정한 프레임과 시각만 기록하며 별도의 충돌 순간속도를 만들어 넣지 않습니다. 거리나 실제 FPS가 없으면 계산 불가능한 값은 `null`로 두고, 실제 입력된 프레임·거리는 보존합니다. 영상 없는 사고의 마커도 프레임은 기록하고 영상/FPS/시각/속도는 `null`로 둡니다. FPS를 임의로 30으로 가정하거나 범주형 차량 속도를 수치로 변환하지 않습니다. 시각은 기존 앱과 동일하게 프레임/FPS로 계산하므로 가변 프레임률 영상의 실제 프레임별 타임스탬프를 측정한 값은 아닙니다.

두 CSV 모두 UTF-8 BOM 형식이며 누락값은 문자열 `null`로 기록합니다. 내보낼 모든 파일을 임시 파일에 먼저 생성한 뒤 교체합니다. Excel 등에서 기존 파일을 열어 두어 일부 교체만 성공한 경우에는 저장된 파일과 실패한 파일을 구분해 안내합니다.

## 다른 PC·폐쇄망 배포

### 권장 방식: EXE 배포 폴더 + 모델 7개 파일

폐쇄망 PC에는 PyInstaller로 묶은 **EXE 배포 폴더**를 옮깁니다. 대상 PC에 Python·pip·가상환경을 설치하지 않으며, 실행 중 인터넷에 접속하지 않습니다. 배포 폴더는 한 파일(onefile)이 아닌 **폴더(onedir)** 형태입니다. 실행할 때마다 수 GB를 임시 폴더에 풀지 않아 시작이 빠르고, Qt(LGPL) DLL을 교체할 수 있는 형태를 유지합니다.

| 항목 | 위치 | 배포 폴더 포함 |
|---|---|---|
| Python 3.11 런타임, PySide6(Qt·QtMultimedia), OpenCV(FFmpeg 포함), NumPy, PyTorch·Torchvision, Transformers·Tokenizers·Safetensors·huggingface-hub, Pillow 및 전이 의존성 | `AVAT\_internal\` | 포함 |
| 글꼴·아이콘·데이터 명세서·Word 서식·검출 분류(`investigator/assets/`) | `AVAT\_internal\investigator\assets\` | 포함 |
| Visual C++ 런타임 DLL(`vcruntime140*.dll`, `msvcp140.dll`) | `AVAT\_internal\` | 포함(빌드 시 존재 확인) |
| Visual C++ 재배포 패키지 설치 파일 | `AVAT\prerequisites\vc_redist.x64.exe` | 포함(DLL 오류가 날 때만 설치) |
| 검출 설정(Grounding DINO, 로컬 모델, `offline: true`, `python` 생략 = 내장 환경) | `AVAT\detection-runtime.json` | 포함 |
| **Grounding DINO 모델 7개 파일**(약 934MB) | `AVAT\runtime\models\grounding-dino-base\` | **미포함 — 별도 반입** |
| 조사 DB·영상·개인 설정 | 각 작업 폴더, `%LOCALAPPDATA%\AVAT`, 레지스트리 `HKCU\Software\AVAT` | 미포함(대상 PC에서 생성) |

모델을 EXE 안에 넣지 않는 이유는 다음과 같습니다.

- 용량이 큽니다.
- 프로그램과 모델을 따로 교체·승인할 수 있습니다.
- 빌드 결과물(GitHub 아티팩트)에 가중치를 올리지 않아도 됩니다.

배포 폴더에는 `배포_안내.txt`(설치·문제 해결), `BUILD-INFO.txt`(소스 커밋·CPU/CUDA 구분), `SHA256SUMS.txt`·`verify-package.ps1`(반입 후 무결성 확인), `runtime\models\grounding-dino-base\MODEL-SHA256SUMS.txt`(빌드 검증에 쓴 모델 파일의 체크섬), `licenses\`(제3자 고지·포함 패키지 라이선스·빌드 패키지 목록)를 함께 넣습니다.

### EXE 실행 구조

- `main.py`가 PyInstaller 진입점입니다. `AVAT.exe`가 `--avat-worker <모듈>` 인자로 다시 실행되면 Qt를 불러오기 전에 영상 디코더(`investigator.video_decode_worker`) 또는 객체 검출(`investigator.detection_worker`) worker로 분기합니다(`investigator/runtime_paths.py`). 소스 실행은 기존과 같이 `python -m <모듈>`을 사용합니다.
- 설정 파일과 `runtime/models/` 상대 경로는 내부 라이브러리 폴더(`_internal`)가 아닌 `AVAT.exe`가 있는 폴더를 기준으로 합니다.
- 창 없는 EXE의 worker 표준 입출력은 UTF-8로 고정해 한국어 Windows(cp949)에서도 진행·오류 메시지가 깨지지 않습니다.
- 보존된 비교용 백엔드(YOLOE·SAM3·EfficientSAM3)의 코드는 남아 있지만 Ultralytics·CLIP 등 전용 패키지는 배포 폴더에 넣지 않습니다. 배포본에서는 Grounding DINO만 사용합니다.

### 배포본 만들기

**GitHub Actions(권장)**: `.github/workflows/build-windows-exe.yml`이 앱 코드·패키징·테스트 파일을 바꾼 push와 수동 실행(`workflow_dispatch`, 기본 브랜치에 워크플로가 있을 때)에서 동작합니다.

1. **테스트**: Windows에서 `ruff`와 `local_dev/tests` 전체를 실행합니다.
2. **빌드**: CUDA 12.8판(`AVAT-windows-cuda`)을 PyInstaller로 빌드하고 배포 폴더를 구성합니다. 포함된 PyTorch에 RTX 50 시리즈용 GPU 코드(`sm_120`)가 있는지도 확인합니다. CPU 전용판이 필요하면 워크플로의 `matrix.variant`에 `cpu`를 추가합니다.
3. **실제 실행 점검**: 빌드한 `AVAT.exe`로 다음을 확인합니다. 검증용 모델은 이 단계가 끝난 뒤 결과물에서 제거합니다.
   - 영상 디코더 열기·탐색
   - 검출: 배포 폴더의 `detection-runtime.json`과 모델 위치를 그대로 사용하고, 앱과 같은 인자로 CPU에서 Grounding DINO 실제 추론을 실행합니다. `HF_HUB_OFFLINE=1`과 연결할 수 없는 프록시를 지정해 인터넷을 차단한 상태입니다.
   - GUI 창 표시
   - `verify-package.ps1` 무결성 확인
4. **업로드**: 결과는 실행 페이지의 **Artifacts**에서 zip으로 내려받습니다(보관 30일).

**Windows PC에서 직접 빌드**(인터넷 연결 필요, 프로젝트 루트):

```powershell
py -3.11 -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
.\.venv-build\Scripts\python.exe -m pip install -r requirements.txt pyinstaller==6.22.3
.\.venv-build\Scripts\python.exe -m PyInstaller packaging/avat.spec --noconfirm --clean
.\.venv-build\Scripts\python.exe packaging/assemble_package.py --dist dist/AVAT --out package/AVAT --variant cuda
# 선택: 모델을 package\AVAT\runtime\models\grounding-dino-base\에 넣은 뒤 실제 실행 점검
.\.venv-build\Scripts\python.exe packaging/smoke_test_exe.py --exe package/AVAT/AVAT.exe --detect
```

`--vc-redist`, `--licenses`, `--freeze`, `--model-dir` 옵션으로 재배포 패키지·라이선스 목록·빌드 패키지 목록·모델 체크섬을 추가할 수 있습니다(워크플로 참고).

### 대상 GPU: RTX 5080 (CUDA 12.8판)

배포 대상은 **NVIDIA RTX 5080**이며 CUDA 12.8용 PyTorch(`torch 2.11.0+cu128`)를 포함한 배포본을 사용합니다.

- **RTX 50 시리즈 지원**: RTX 50 시리즈(Blackwell, `sm_120`)는 CUDA 12.8 이상으로 빌드한 PyTorch가 필요합니다. 빌드 서버에서 포함된 PyTorch의 `sm_120` 지원을 확인합니다.
- **대상 PC 요구 사항**:
  - Windows 10/11 64비트
  - NVIDIA 그래픽 드라이버(RTX 50 시리즈는 R570 이상)
  - CUDA Toolkit·cuDNN은 배포 폴더에 포함되어 있어 따로 설치하지 않습니다.
- **검출 설정**: `device: "auto"`와 `dino_fp16: true`(기본값)로 GPU FP16 추론을 사용합니다. GPU를 찾지 못하면 자동으로 CPU로 실행되지만 매우 느립니다(빌드 서버 4코어 CPU 기준 4프레임 약 250초). 이때는 그래픽 드라이버를 확인하세요.
- **용량**: 배포 폴더 약 4.5GB(zip 약 3.0GB)이며 대부분이 CUDA 라이브러리입니다. 모델 7개 파일(약 934MB)은 별도입니다.

### 다른 PC로 옮기는 방법

1. **준비**: 인터넷이 되는 PC에서 다음 두 묶음을 준비합니다.
   - Actions 아티팩트 `AVAT-windows-cuda` zip(약 3.0GB, 또는 직접 빌드한 `package\AVAT`)
   - 모델 7개 파일 폴더. 기존 `runtime\models\grounding-dino-base\`를 그대로 씁니다.
2. **반입**: 두 묶음과 각 SHA-256 값을 승인된 반입 매체나 망연계 절차로 옮깁니다. 모델은 프로그램을 업데이트할 때 다시 옮길 필요가 없습니다.
3. **설치**: 대상 PC의 `C:\AVAT`처럼 쓰기 가능한 로컬 경로에 압축을 풉니다. 모델 7개 파일은 `C:\AVAT\runtime\models\grounding-dino-base\`에 복사합니다.
4. **확인**: `powershell -ExecutionPolicy Bypass -File .\verify-package.ps1`로 프로그램·모델 파일을 확인합니다.
5. **실행·점검**: `AVAT.exe`를 실행하고 영상 열기·재생·저장·CSV·보고서와 Grounding DINO 단일 프레임/구간 검출·취소를 확인합니다.

다른 PC에서 이전 설정(다른 모델·Python 경로)을 저장한 적이 있으면 **설정 → 객체 검출 환경…**에서 Grounding DINO와 배포 폴더의 모델 경로로 바꾸고, **검출용 Python은 비워 둡니다**. 기존 작업을 이어갈 때만 앱을 정상 종료한 뒤 프로젝트 폴더(`investigations.db`와 연결 영상)를 함께 옮깁니다.

### GitHub 사용 기준

- **코드 백업**: 패키징 전에 소스를 커밋·push하는 것이 좋습니다. `BUILD-INFO.txt`에 소스 커밋이 기록되므로 배포본이 어느 코드에서 만들어졌는지 추적할 수 있습니다. 작업 브랜치에서 검증한 뒤 `main`에 병합하고, 배포한 버전에는 태그(예: `v0.1.0`)를 붙이는 방식을 권장합니다.
- **EXE·가중치는 Git에 커밋하지 않습니다.** GitHub는 100MB가 넘는 파일을 거부하고, 커밋한 대용량 파일은 삭제해도 저장소 기록에 남습니다. `.gitignore`가 `dist/`·`build/`·`*.safetensors`·`runtime/models/` 등을 제외합니다.
- **EXE 배포본 보관**: Actions 아티팩트(30일 보관) 또는 GitHub Release 첨부 파일(파일당 2GB 제한)이 일반적인 방법입니다. CUDA판 zip은 약 3.0GB라 Release에는 분할이 필요합니다. 아티팩트는 기한이 지나면 삭제되므로 내려받아 승인된 내부 파일 서버에 보관하세요.
- **공개 저장소 주의**: 현재 저장소는 공개(public)이므로 코드·작업 브랜치·Actions 아티팩트도 외부에서 볼 수 있습니다. 내부 전용 프로그램이면 저장소를 비공개로 바꾸는 것을 검토하세요. 비공개 저장소는 Actions 무료 사용량(월 실행 시간, 아티팩트 저장 용량 500MB)이 제한되어 수 GB의 배포본은 Actions 아티팩트로 보관하기 어렵습니다. 이 경우 직접 빌드한 결과를 내부 저장소에 보관합니다.
- **모델 가중치**: `IDEA-Research/grounding-dino-base` 모델 카드는 Apache-2.0을 표시하지만, 반입·재배포는 기관 승인 절차를 따르세요. 출처·체크섬(`MODEL-SHA256SUMS.txt`)을 함께 기록합니다.

### 프로젝트 루트의 `Ultralytics/`·`runs/` 폴더

`Ultralytics/`·`runs/`는 과거 기본값이던 **YOLOE**로 검출을 실행할 때 Ultralytics 라이브러리가 만든 폴더이며, 다음 두 가지로 생깁니다.

- **`Ultralytics/`**: 설정 폴더(`YOLO_CONFIG_DIR`)를 지정하지 않으면 Ultralytics가 기본 위치나 현재 작업 폴더에 설정 파일을 만듭니다.
- **`runs/segment/predictN`**: `save=False`로 예측해도 매번 빈 예측 폴더를 만듭니다.

현재 YOLOE 코드는 두 폴더를 검출 작업의 임시 폴더로 보내므로 새로 생기지 않습니다. Grounding DINO 실행·EXE 배포에는 **두 폴더 모두 필요하지 않습니다**. 개발 PC에 남은 폴더는 안에 설정 파일과 빈 `predict` 폴더뿐인지 확인한 뒤 삭제해도 됩니다. Git에서는 이미 제외되어 있습니다.

### 소스 실행 방식으로 옮길 때(대안)

EXE를 쓰지 않고 소스와 Python 환경을 옮길 수도 있습니다. 인터넷이 되는 준비 PC에서 다음 휠을 모두 `wheelhouse\`에 받아 함께 반입합니다.

- 대상 Windows·Python·CPU/GPU에 맞는 **전이 의존성까지 포함한 휠 전체**
- GPU/CPU에 맞는 torch·torchvision 휠

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --no-index --find-links .\wheelhouse -r requirements.txt
Copy-Item .\detection-runtime.example.json .\detection-runtime.json
.\.venv\Scripts\python.exe main.py
```

가상환경 폴더는 PC 간에 복사하지 말고 대상 PC에 새로 설치합니다. 이 방식은 대상 PC에 Python 3.11~3.13 64비트 설치가 필요하므로, 폐쇄망 배포에는 EXE 방식을 권장합니다.

**반입하지 않아도 되는 항목**:

- 다른 모델의 가중치·임베딩 캐시·연구 소스
- `runtime/checkpoints/`, `runtime/tokenizers/`
- `Ultralytics/`, `runs/`, `outputs/`
- 다운로드 캐시·로그
- 개발용 `local_dev/`

### 검증 결과와 남은 확인 사항

**빌드 서버에서 확인한 사항**(GitHub Actions Windows, 소스 커밋은 배포본의 `BUILD-INFO.txt` 참고)

- 공유 테스트 `local_dev/tests` **852개 통과·1개 건너뜀**(Windows, CPU PyTorch). 같은 테스트 중 2개 파일은 Linux offscreen에서만 Qt 네이티브 오류로 중단되며 Windows에서는 통과합니다.
- PyInstaller 빌드 성공: `AVAT.exe` + `_internal`. Visual C++ 런타임 DLL 포함 확인. 배포 폴더 약 4.5GB(5,339개 파일), zip 약 3.0GB.
- `verify-package.ps1`: 프로그램 파일 전체와 모델 7개 파일 체크섬 일치.
- 빌드한 `AVAT.exe`로 다음을 확인했습니다.
  - **디코더 worker**: 810×1080 영상 열기·탐색
  - **Grounding DINO 실제 추론**: 인터넷을 차단한 상태에서, 배포 폴더의 `detection-runtime.json`과 `runtime\models\grounding-dino-base`를 그대로 사용
    - 샘플 사진(버스·보행자) 4프레임에서 검출 8개(차량 4·도로낙하물 4)
    - 진행·완료 이벤트의 UTF-8 전달 정상
  - **GUI**: `AVAT` 창 표시, 진단 로그에 오류 없음
- 빌드 서버에는 GPU가 없어 검출은 CPU로 실행됐습니다. 이로써 CUDA판이 GPU가 없을 때 CPU로 자동 전환되는 것을 확인했습니다.
- 이전 CPU판 빌드(같은 코드)도 같은 점검을 통과했습니다(배포 폴더 770MB). 현재 배포 대상에서는 제외합니다.

**아직 확인하지 않은 사항(대상 PC에서 확인 필요)**

- **RTX 5080에서의 실제 GPU(FP16) 추론과 속도.** 빌드 서버에 GPU가 없습니다. 대상 PC에서 단일 프레임과 짧은 구간 검출로 먼저 확인하세요. 작업 관리자의 GPU 사용률로 GPU 사용 여부를 볼 수 있습니다.
- 실제 폐쇄망 PC의 백신·SmartScreen·보안 정책 영향, 긴 실제 사고 영상 처리, 장시간 사용.
- 검출 품질: 샘플 사진의 보행자가 현재 임계값(박스 0.30, 표시 신뢰도 0.50)에서 검출되지 않았습니다. 실제 영상으로 임계값을 검토하고 라벨은 반드시 사람이 확인하세요.
- 레거시 회귀 테스트 `local_dev/avat-detection-tests`는 이번 검증에 포함하지 않았습니다. 이전 점검에서 기존 UI 속성·세분류 계약을 기대하는 일부 테스트가 실패했습니다.
- 모델 가중치·배포 라이브러리의 반입·재배포 승인(`licenses\` 폴더의 고지 참고).

## 저장소 설정

`.gitignore`는 공통 제외 규칙, `.gitattributes`는 줄바꿈·바이너리 처리 규칙, `pyproject.toml`은 패키지·실행 명령과 공통 도구 설정을 관리하므로 저장소에 포함합니다. 개인 작업 경로의 제외 규칙은 Git이 추적하지 않는 `.git/info/exclude`에서 관리합니다. 이 파일은 다른 환경으로 복제되지 않으므로 새 환경에서는 개인 규칙을 별도로 설정해야 합니다.

앱·객체탐지 코드와 함께 `local_dev/`의 테스트·도구·시안·패치·문서와 `runtime/tools/`의 기존 연구 도구를 보존합니다. 과거 타모델용 코드·테스트·예시는 보존 자료이며 현재 Grounding DINO 설치·배포에 포함할 의존성이나 준비물을 뜻하지 않습니다. `avat_ai/`는 별도 프로그램이라 이 저장소에 포함하지 않습니다. 가중치·모델 다운로드 자료·가상환경·실제 DB/영상·비밀 설정·생성 결과물(`outputs/`, `runs/`, `Ultralytics/`, `dist/`, `build/`, `package/` 등)은 제외합니다. EXE 배포본은 Git이 아니라 Actions 아티팩트나 내부 저장소로 관리합니다. 실행 환경 설정은 `detection-runtime*.example.json` 예시만 공유합니다. 별도 Git 저장소로 복제한 연구 소스는 제외를 유지하며 Grounding DINO 배포에 필요하지 않습니다.

앱 실행에 필요한 코드는 `investigator/`, 번들 자산은 `investigator/assets/`에 둡니다. CSV 내보내기에 쓰이는 데이터 명세서와 글꼴·아이콘 및 해당 라이선스도 배포에 포함합니다.
